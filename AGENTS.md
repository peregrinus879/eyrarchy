# AGENTS.md - EyrArcHy

Personal [Omarchy](https://github.com/omacom/omarchy) dotfiles managed with [GNU Stow](https://www.gnu.org/software/stow/): targeted personal deviations stowed on top of the Omarchy desktop (Bash overrides and a native Herdr layout helper in `bash/`, Hyprland personal overrides in `hypr/`, additive Neovim vault and Git-review plugin specs in `nvim/`, Yazi config in `yazi/`). Omarchy, official docs, official package docs, and `DEVIATIONS.md` are the source of truth for default behavior and intentional differences; ownership boundaries live in `DEVIATIONS.md` (Deviation Policy and Out Of Scope).

## Load Map

- Claude Code (2.1.277 or later) and OpenCode read this file natively as the project's `AGENTS.md`; the repository has no `CLAUDE.md`, which would take precedence in Claude Code. Skills load on invocation only.
- The `Makefile` is the single source of the package list (`scripts/prepare-stow.sh` consumes it); `references.txt` lists this repository's reference clones. Reference maintenance can include the explicitly selected EyrWSL peer, never arbitrary neighboring repositories. `README.md` is the overview; `docs/setup.md` owns installation/recovery and `docs/operations.md` owns usage, verification, and routine maintenance. `DEVIATIONS.md` owns architectural boundaries and intentional differences; script headers own local constraints. Link to each owner rather than repeating its procedures in the README.
- `docs/maintenance.md` owns unresolved decisions, deferred work, active limitations, and dated revalidation evidence; read it before package removals, Omarchy updates or refreshes, or work on a deferred item. Prose describes current behavior; Git history owns provenance.
- EyrAgents owns the [full offline workspace guide](https://github.com/peregrinus879/eyragents/blob/main/docs/workspace-guide.html) and its [maintenance contract](https://github.com/peregrinus879/eyragents/blob/main/docs/workspace-guide-src/README.md). In-scope control changes include reconciliation of its `host-reference.json`; `/omasync` owns host/default and launcher fact review, while `/eyrsync` owns client controls. Obtain EyrAgents companion edit scope when needed; unavailable or unauthorized reconciliation remains explicit in this repository's maintenance ledger. EyrAgents builds/checks the guide independently; `twins` protects the host implementation files.

## Invariants

- Target machine: Omarchy. `stow`, `unstow`, `restow`, `clean`, `recover`, and `verify` refuse elsewhere. Every host-writing Make target requires the deployed-clone guard before mutation, checking managed endpoints and parents; `.NOTPARALLEL` serializes one Make invocation, not independent deployments. `lint`, `check`, `test`, `twins`, `twins-pair`, and `refs` run anywhere.
- Because the packages are live configuration on the stowed host, an edit to a stowed file here is active for the next shell, Hyprland reload (Hyprland reloads on save), Neovim session, or Yazi launch before any commit; work on this repository only in a session H is watching.
- Stow runs with `--no-folding`, so every managed parent under `$HOME` is a real directory and only leaf files are links; generated host state therefore never reaches a package source. `make clean` preflights the complete owned layout and removes only owned folded links, recognized dangling clone links, and exact retired links. The retired `~/.config/bash/functions/tdw` endpoint maps only to this clone's former `bash/.config/bash/functions/tdw`, independently of Git's current inventory. Unsafe parents, regular files, foreign links, and special files refuse unchanged; real directories and user state stay. After pulling a retirement, run guarded `make clean` then `make restow`; restow alone does not perform retirement cleanup. `make verify` checks retirement read-only, including pending known deletions and post-pull absence, and fails on unrelated missing sources or folded managed directories. Preflight is preservation-safe refusal, not rollback against I/O failure or concurrent host edits.
- When editing sibling dotfiles repos, use identical wording for shared concepts; only repo-specific values (scope, package lists, invariants) differ.
- GitHub access uses host-local `gh` authentication and HTTPS remotes. H owns login and storage choices; helper settings belong in untracked `~/.config/git/config.local`, never Stow sources. Authentication does not authorize repository mutations. Setup and operations own onboarding and fresh-session/reboot checks.
- `git-review.lua` keeps Git diff/origin-diff/status tied to the current file or Neo-tree selection, not an unrelated launch directory. Resolve the context on each key invocation without changing editor cwd; known non-Git targets warn rather than choosing another repo. The spec and regression suite are twins; keep upstream base config and plugin caches untouched.
- The Makefile `TWIN_SPECS` files (Neovim plugin specs, `hdw`, Yazi config, reference updater and their declared tests/fixtures) are byte-identical across EyrArcHy and EyrWSL. Local `make twins` checks worktrees and can skip a missing sibling. `twins-pair` carries `SELF_COMMIT`, `PEER_COMMIT`, and `SIBLING` as literal data, not Make expressions or shell source; it requires two full commit IDs and compares committed blobs, failing on missing objects/files without executing peer code. CI checks the peer default branch normally; an explicit manual-dispatch peer requires `peer_reviewed=true` and records both actual commits. Final publication evidence must name the final published pair, not an arbitrary earlier green peer.
- `make refs` reports and keeps stale clones, never inferring deletion safety from HEAD or cleanliness. Listed default branches must reach exact fetched upstream parity by fast-forward; ahead-only/divergent branches refuse. Atomic, non-forced fetches preserve existing local tags and annotations while importing new tags and pruning only origin tracking branches. Checkout and merge use `--no-overwrite-ignore` to preserve ignored files in listed clones. Tag/file conflicts refuse that update and require separate review, not forcing or deletion. Manual disposal needs separate review of all refs, stashes, and ignored/untracked content.
- `hdw <cc|oc> [-c]` creates and focuses a new native Herdr workspace in the caller's current physical directory, not the Git root. Run it inside an already-running Herdr; the caller's tab may be populated, and repeated calls create separate workspaces even in the same directory. AI stays full-height left, Neovim top-right and shell bottom-right, with equal columns, equally stacked right panes and AI focus. Naming stays with Herdr; existing labels/layouts are not rewritten. No workspace reuse/registry, rename/metadata writes, server startup or outside attachment; bare `hdw` is usage. Leave old state/recovery files unused and untouched. Validate the caller, pre-creation workspace inventory, new root's opaque terminal identity, exact membership and complete geometry before input; serialize cooperating calls. Cleanup may close only proven new split panes before input, never any workspace/tab/root or the original caller. A new workspace/root is retained for inspection on failure; possible input or uncertain ownership preserves remaining state with original/new recovery context. These multi-call workflows are not server-side atomic transactions.
- Omarchy owns its AI launch aliases, Herdr recipes and installed tmux package/configuration/functions/launch binding; load them unchanged, without copying or overriding `hdl`/`hdlm`. The `cc`/`oc` arguments belong only to `hdw`, which sends full tool names with no stock alias flags. Stock `c`/`cx`/`cy` select OpenCode/Claude Code/Codex respectively; stock `cx` and `hdw cc` both start Claude Code. Clients load their normal user configuration. Do not refresh defaults or reset sessions for custom `tdw` retirement.
- Omarchy must be installed and functional before applying these dotfiles; Yazi is installed separately (`sudo pacman -S yazi`).
- The vault is expected at `~/Projects/vault` (override with `OBSIDIAN_VAULT`) for the obsidian.nvim workflow.
- Git identity lives in the untracked per-host `~/.config/git/config.local`; `make verify` asserts that it resolves to a GitHub no-reply address without printing it.
- The `hypr` package carries personal Hyprland overrides only, loaded after the Omarchy defaults through the Omarchy-owned `~/.config/hypr/hyprland.lua` require chain: `bindings.lua` (the twelve default web-app bindings retired via `hl.unbind`, the personal `SUPER ALT` set and AppImages added), `monitors.lua` (display values), `input.lua` (us/ara layouts, natural scrolling), and `looknfeel.lua` (rounded corners, reduced gaps); no defaults are replicated (deviations documented in `DEVIATIONS.md`). Keep native `SUPER G`/`SUPER ALT G` grouping controls unshadowed; ChatGPT web uses `SUPER ALT C`, distinct from its desktop app on `SUPER SHIFT C`. `make verify` asserts every `hl.unbind` target against the installed defaults and fails on a personal chord that collides with a default not unbound above it.
- Keep every intentional difference documented in `DEVIATIONS.md`; update the overview, agent invariants, and affected setup/operation guides together when ownership, setup, or sync assumptions change.
